## 1. 三個版本的差別

| | A＋（現在） | 2.5D（本方案） | HD-2D |
|---|---|---|---|
| 場景 | 2D 分層圖片 | **3D 模型**（牆、柱子、車都有厚度） | 同一套 3D 場景，再加精緻度 |
| 人物 | 2D 像素圖 | 同一批像素圖立在 3D 空間（`AnimatedSprite3D`） | 同左 |
| 鏡頭 | 2D 正側面 | **3D 透視鏡頭**，側面略往下看（約 10～15 度） | 俯角 30～45 度、窄視角 |
| 深度 | 圖層順序與 y 座標 | **真的前後**：越遠越小、走到柱子後面會被擋住 | 同左 |
| 光影 | 2D 燈光 | **3D 燈光**、陰影落在地面與牆上 | 加上真正的景深、體積霧、SSAO |
| 平台 | 網頁 | **網頁**（Compatibility） | 桌面版（Forward+） |

玩法仍是橫向捲軸：主要左右走，可以前後移動（縱深帶變成真的 Z 軸）。

## 2. 專案策略（作者 2026-10-14 決定）

- 開始時**複製一份新專案**（例如 `失語者_2.5D`），**A＋ 的網頁版不動**，保留成完成的版本。
- 渲染器維持 `gl_compatibility`，維持網頁匯出。
- 可以直接沿用：
  - `data/story.json`、`data/areas/*.json`（劇本、區域、條件、結局）
  - `GameState`（旗標、物品、數值、檢查點）、衝動機制
  - `main.gd` 的 UI（對話框、打字機、選項、標題、結局）：UI 在 CanvasLayer 上，疊在 3D 畫面上照樣能用
  - A4 的全部聲音（位置音效改用 `AudioStreamPlayer3D`）
  - 全部像素人物與 A3 的動畫、劇本檢查工具、大部分遊玩測試
- 要改寫：區域系統（2D → 3D）。

| 2D（A＋） | 3D（2.5D） |
|---|---|
| `Node2D` 區域根節點（`y_sort_enabled`） | `Node3D`（前後由深度決定，不需要 y 排序） |
| `CharacterBody2D` 主角 | `CharacterBody3D`，沿 X 走、Z 前後 |
| `AnimatedSprite2D` | `AnimatedSprite3D`（Nearest、alpha cut、`pixel_size`、開啟陰影投射） |
| `Area2D` 互動點 | `Area3D` |
| `Camera2D`＋`camera_fx.gd` | `Camera3D` 跟隨、邊界限制，推近／震動／晃動改寫成 3D |
| `Parallax2D` 分層 | 物件放在真正不同的 Z |
| `PointLight2D`、`LightOccluder2D`、法線貼圖 | `OmniLight3D`／`SpotLight3D`、即時陰影 |
| `AudioStreamPlayer2D` | `AudioStreamPlayer3D` |
| 區域資料的 `x` | 換算成 3D 的 X（必要時新增 `z`） |

## 3. 3D 模型的來源（作者 2026-10-14 決定的順序）

| 優先 | 來源 | 用法 |
|---|---|---|
| 1 | **Blender MCP**（`mcp-for-blender`，原名 `blender-mcp`） | 先用它實驗建模：燒毀的車、柱子、櫃子、牆面模組等；B2 起匯出 `.gltf`＋`.bin`（不用 `.glb`，原因見 `docs/2.5D_區域樣板流程.md`） |
| 2 | **Godot 基本形狀＋像素貼圖** | 能沿用的先沿用：方塊、平面（`MeshInstance3D`／CSG）貼上 Pixelorama 畫的貼圖或 A1 的現有素材 |
| 3 | 免費素材包（例如 Kenney，CC0） | 最後才用：前兩種做不出來或太花時間的物件 |

三個 MCP 的分工：

| MCP | 負責 |
|---|---|
| Blender MCP | 建模、UV、材質、匯出 `.gltf` |
| Pixelorama MCP | 像素貼圖（B2 起：設計腳本畫好再匯入、存 `.pxo`、匯出 PNG）、人物與動畫（沿用 A3） |
| godot-mcp-toolkit | 組場景、燈光、腳本、執行、截圖、驗證 |

外部素材一樣要記進 `docs/素材來源.md`。

## 4. 透視與像素的衝突

透視鏡頭會讓遠處的人物變小，像素圖就不是整數倍放大（A1.5 曾因此決定不縮放）。處理方式（作者 2026-10-14 同意）：

- **B0 時做兩種截圖給作者比較**：
  1. **接受縮放**：HD-2D 遊戲的做法，人物隨距離變大變小。
  2. **縮小縱深帶**：前後能走的範圍變窄，人物大小幾乎不變。
- 兩種都用 Nearest 取樣、alpha cut，避免邊緣模糊。

---

### B0 的決定（作者 2026-10-20）

> B2 起有兩項已改：鏡頭換成 B（主角約 214 px，縱深不再是 ±9%）、停車場的環境光改成 0.5（青綠）；見下方「B2 的決定」與 B2-5。

- **縱深帶採用做法 1（接受縮放）**：縱深帶 3 公尺，人物前後大小差約 ±9%（視角 40 度、鏡頭距離 14.3 公尺）；比較圖 `art/design/b0/b0-1_縱深兩種做法.png`。參考歧路旅人：接受縮放，用強景深與整體氛圍讓像素不整齊變得不明顯。
- **主角補正面、背面的走路與待機**（`assets/sprites/player_fb.png`，B0-3 完成）：往畫面裡外走時用背面／正面，有左右方向時用側面。其他人物多半站著，先只補主角。
- **人物受光＋調亮環境光**（環境光 1.2）；之後 B4 可以再把 A2 的法線貼圖接進 3D。
- **景深強度先照 B0-2 的設定**（`max_radius` 12px、`far_ramp` 3、`near_ramp` 2.5），有問題再調。
- 主角沿用像素圖、不做 3D 模型。

## 5. 網頁版做不到的效果：替代方案（作者 2026-10-14 決定的順序）

Compatibility 渲染器**不支援景深模糊、體積霧、SSAO**；3D 燈光、即時陰影、光暈、烘焙光照可以用。

| 優先 | 方案 | 做法 | 代價 |
|---|---|---|---|
| **第一（採用）** | **A. 自己寫 shader 模擬** | 景深：依和鏡頭的距離模糊（遠景、前景分開處理）；體積霧：A2 的霧 shader 貼在 3D 半透明平面上，多層疊出厚度；光束：A2 的光束 shader 改成 3D 錐形；角落陰影：烘焙光照（Blender 或 Godot） | 要花時間調；效果約八成 |
| 第二 | B. 預先算圖 | Blender 把場景（含景深、體積霧）算成高品質的圖當背景，加深度資料讓人物能走到物件後面 | 鏡頭幾乎不能動，本質回到 2D |
| 第三 | D. 2.5D 也做桌面版 | 改用 Forward+，所有效果都有 | 失去網頁版，等於直接做 HD-2D |
| 最後 | C. 改用網頁 3D 引擎 | PlayCanvas、Babylon.js 等，內建景深、SSAO | 遊戲邏輯用 JavaScript 全部重寫，Godot MCP 的經驗用不上 |

A 在網頁上跑不跑得動、效果夠不夠，在 **B0** 驗證；不夠時依序考慮 B → D → C，換方案前先問作者。

> B0-2 結果：A 的景深（自己寫的 shader，焦點跟著主角）與一層 3D 霧在網頁版（Chrome）FPS 90～100，效果作者接受，**維持方案 A**。shader 在 `shaders/b0_dof.gdshader`、`shaders/b0_fog3d.gdshader`。

### B1 的決定（作者 2026-10-20）

- 2D 區域保留，用一個開關切換 2D／3D（B5 再決定要不要刪掉 2D）。
- 3D 灰盒場景的互動點用轉換工具從 2D 場景一次產生初稿，之後用 Toolkit 檢查與修改。
- `data/areas/*.json` 維持 2D 的像素座標，3D 區域裡換算（64 像素＝1 公尺，縱深帶 650～735 ↔ 前後 3 公尺）。
- 人物先能用就好（沿用像素圖、A3 動畫、受光＋環境光），精修留給 B4。
- 分步：B1-1 3D 基礎元件 → B1-2 接上 Main → B1-3 停車場 → B1-4 其餘 6 區 → B1-5 測試與收尾（`PROMPTS.md` 的「2.5D B1 分步指令」）。
- 景深（B1-3 後，作者 2026-10-20）：採用 **A**＝焦點仍跟著主角，清楚的範圍從前後 1 公尺放寬到 2 公尺（範本 `AreaBase3D.tscn` 的 `focus_range = 2.0`），讓走道上的道具、人物大多清楚；**備案 B**＝整條走道固定清楚、只有後面與前面模糊（《歧路旅人》的移軸式），A 不夠時再改。對照圖 `art/design/b1/b1-3_景深比較.png`。
- 場景素材（作者 2026-10-20）：B1 維持灰盒，不先搬 2D 的背景插畫與中景圖，B2 再做模型。

### B2 的決定（作者 2026-10-21，B2-0）

- **模型風格**：低多邊形＋像素貼圖（32 像素＝1 公尺，和人物的像素密度相同）；結構、車子、燈具，**連可調查的小道具（血跡、照片、地面殘骸、門）也建模**；地上的近景小物、人物照舊是像素圖（人物 B4 精修）。
- **天花板**：**真實 3 公尺＋降低鏡頭**。主角在畫面上 96 像素時，畫面在主角的深度約涵蓋 12 公尺高，3 公尺的空間只佔約 1/4，所以鏡頭有三種做法要先比較：A 平視（縱深帶在畫面上變扁）、B 主角變大＋鏡頭拉近（像素 4 倍、7 區都要重調）、C 切掉前面的天花板（畫面上方是暗的）。B2-1 先做鏡頭比較截圖（`art/design/b2/b2-1_鏡頭比較.png`），**作者選 B（2026-10-21）**：鏡頭距離約 7.2 公尺、高約 2.2 公尺、往下看約 5°，主角在畫面上約 214 px、前後走差約 136 px；距離之後可在 8～10 公尺之間微調。取代 B0 的鏡頭（7 區都跟著變）；人物照新的大小重畫留給 B4，在那之前先用現在的像素圖放大。
- **縱深感**：後牆推到約 9 公尺深，中間有停車格、車子、兩排柱子，越遠越暗；不用原圖當後牆貼圖。
- **素材來源**：全部用 Blender MCP 自己建；Poly Haven、Sketchfab、AI 生成維持關閉。
- **新素材**（作者 2026-10-21）：「2.5D 版和原本的版本不一樣，所以做新的素材沒問題」——A＋ 的像素圖與構圖只當參考；鏡頭或主角大小改了之後，人物、道具要重畫也可以（例如選鏡頭 B 時重畫比較大的人物，而不是把現有像素圖放大 4 倍）。

### 驗證方式（沿用 A＋ 的做法）

- `game_start` → `input_simulate` 走路 → 讀主角 3D 座標，確認移動、邊界、鏡頭跟隨。
- `runtime_screenshot`（disk 模式）確認前後遮擋、光影、透視。
- 遊玩測試（`tests/`）改成 3D 版後全部通過；劇本檢查改成檢查 3D 區域場景的 `point_id`。
- 每一級匯出網頁版，在瀏覽器確認順暢度。

## 7. 主要風險

| 風險 | 對策 |
|---|---|
| 網頁版 3D 效能不足（陰影、多盞燈、半透明霧疊太多層） | B0 就匯出測試；燈光數量、陰影解析度、霧的層數都留參數 |
| 像素人物在 3D 光照下的樣子（太亮、沒影子、邊緣閃爍） | B0 確認 `AnimatedSprite3D` 的 shaded、alpha cut、陰影設定 |
| Blender MCP 不穩定 | B2 實際遇到：重設 Blender、在程式裡刪節點時斷線，Blender 也自己重開過一次 → 步驟切小、每步存檔、不用 `read_factory_settings`；做不出來時改用 Godot 基本形狀，最後才用素材包 |
| shader 模擬的效果不夠 | 依第 5 節的順序換方案，換之前問作者 |
| Toolkit 的 3D 工具有限 | 做不到的部分寫在腳本或直接編輯 `.tscn`，並記錄原因 |

## 8. 和 HD-2D 的關係

2.5D 做好的 3D 場景、Blender 模型、3D 區域系統、3D 版測試，HD-2D 都能沿用。HD-2D 要做的變成：渲染器改 Forward+（桌面版）、鏡頭改成俯角窄視角、把第 5 節的模擬效果換成真正的景深、體積霧、SSAO。
